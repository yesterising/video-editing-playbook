# 动效与剪映实战经验

来源：作者的自动剪辑口播实践。这里记录制作方法与历史项目现象；执行流程以 [SKILL.md](../SKILL.md) 中用户最新偏好为准，直接制作正式素材，完成全部同步准备后由用户最后拖入工程，测试验收由用户负责。部分风格经验仅来自静态截图，未验证参考视频的完整动态表现。

## 已验证的制作方法

- 语义映射：完成状态→勾选/进度线；情绪时间→时钟；材料投喂→视频、音频、字幕文件汇入；素材查找→关键词与候选缩略图；剪辑→时间线拼装；包装→字体、运动与营销重点；转化→单一关键词和具体资料。复用映射方法，数字、色彩、场景数和 CTA 以最新脚本为准。
- HyperFrames/GSAP 采用单一、可 seek 的时间线；入场、稳定阅读、出场分开安排。素材飞入、缩放、旋转、扫描线、字级强调和音效共同建立动作节奏。高密度作品也保留主要信息的阅读时间。
- 透明动画直接制作正式版本，依据已有工程和可复用制作经验选择格式；最终拖入按主 skill 的交接流程执行。
- 历史工程 ProRes 4444 文件具备 Alpha，但剪映预览出现黑底；QTRLE MOV、ARGB 在该工程实测保留透明和半透明。这是选型参考，不能宣称 ProRes 在所有剪映版本失效。透明动画独立轨、无音频，时间线保留原声一份。
- 已有字幕位置、高亮、字体和时序作为新增动画的布局基准。侧卡避开脸；需要覆盖人物的效果演示段主动安排构图，并检查实际头部和手势范围。
- 加密草稿的必要编辑通过编辑器界面完成，不改写加密字段。正式素材在制作时排好起点、时长、尺寸和同步关系；可靠导入媒体库后，将目标轨道与层级说明交给用户执行最后拖入。
- 音效按动作节点设计：扫屏配 whoosh，落地配轻冲击，筛选配提示，结尾配轻亮音。相邻节点避免连续同响度提示，音效与音乐音量以口播清晰为设计目标，沿用工程已有设置。
- 默认剪到当前工程即结束。只有用户明确要求导出时才处理导出参数；需要兼容成片时，可通过媒体技能输出 H.264、AAC、BT.709 与 faststart，按交付需求选择。

## 创意提升方向：尚待具体成片验证

优先提高证明力、空间关系和镜头差异，别只增加卡片与进度条。

1. **先展示成果。** 开头用少量差异明显的实际成片镜头，再回到人物解释。风格选择须符合主题及实际素材。
2. **给观众对比。** 同一素材做原始→包装后的可见变化，展示字体、节奏、构图如何改善。实际效果未产生前，界面只能作为示意。
3. **展示判断过程。** 找素材表现关键词→候选→排除不匹配→选中→落入时间线。真实录屏与选择结果更可信；模拟界面标“流程示意”。
4. **让内容推动转场。** 文件卡变缩略图、缩略图变时间线、播放头放大进入镜头。扫屏少量强调，其余转场随语义变化。
5. **人物与图形互动。** 采用人物小窗或经验证的同步抠像，让图形从身后穿过、手势旁出现信息。大面板盖住上部却留下半截躯干容易像 PPT 叠口播，需审查构图。
6. **强弱有差。** 爆发、短暂停顿、细节连击交替；关键字落稳再补细节。按手机尺寸检查，字量、动画密度和音效密度分别控制。
7. **资料具体可见。** 结尾围绕一个关键词，展示用户真实提供的教程目录、文档页或交付清单；没有资料时用清晰示意，不制造不存在的教程内容。

## 可编辑范围与完成通知

整段透明 MOV 在剪映只能改整体位置、时长、速度和效果，内部文字与关键帧需回到 HTML/GSAP。需要后期调整时，按场景制作独立正式片段、音效按段组织，常改标题和关键词尽量留为编辑器原生文字。不要把烘焙动画称为原生关键帧工程。

剪辑完成即停止并告知用户，按主 skill 的完成条件执行。用户同时操作时只获取继续编辑所需的当前状态并保护其改动。用户叫停立即停止，不追加保存、导出或验收步骤。
